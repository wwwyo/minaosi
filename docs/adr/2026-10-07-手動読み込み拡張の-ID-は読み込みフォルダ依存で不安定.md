# 手動読み込み拡張の ID は読み込みフォルダ依存で不安定

- Status: Accepted
- Date: 2026-10-07

別 checkout（worktree 等）から読み込むと別 ID になり、本番 Worker `minaosi-review` の `ALLOWED_ORIGINS` に未登録だと 403 になる（main でビルドし新 ID の origin を登録して 204 化を確認）。読み込み先ごとの登録運用を回すか、Store 配布による固定 ID 化が課題。実画面の診断では `chrome:control-chrome` が権限確認（"saved browser permissions could not be verified"）で止まり、agent-browser の検証用 Chrome は別 profile のため note ログインが壁になった — 普段の Chrome で `chrome://inspect/#remote-debugging` を有効化して接続する経路で診断できた
